Merge Conflict 視覺化對比

兩個人都改同一段時，Git 不知道要選誰，所以停下來問你。

Current Change
def login(user): return "Welcome, user"

你目前所在分支的內容。

Incoming Change
def login(user): return f"Welcome back, {user}"

另一個分支要合進來的內容。

Resolved Result
def login(user): return f"Welcome, {user}"

你人工決定後的最終版本。

解 conflict 的重點

不是只打 git add 與 git commit，而是先判斷哪段內容應該被留下。

Git 工作關卡

Unit 1

git init / status

先開始一個 repo，再知道怎麼看狀態。

技術

初始化與觀察狀態。

用途

新專案開始時最常見。

提醒

status 幾乎天天用。

Unit 2

add / commit / log

把修改送進歷史。

技術

先 add，再 commit。

用途

把工作切成可追蹤的小步。

提醒

訊息要清楚。

Unit 3

branch / switch / merge

功能開發不要直接改 main。

技術

建立、切換、合併分支。

用途

多人協作更安全。

提醒

merge 前先看差異。

Unit 4

fetch / pull / push

開始接近團隊同步。

技術

fetch 比 pull 更保守。

用途

先了解遠端，再決定同步。

提醒

不確定就先 fetch。
