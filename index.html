1. Git 是什麼？

Git 是版本控制工具，會記錄檔案的修改歷史。你可以把它想成程式碼的存檔紀錄和時光機。GitHub 是放 Git 專案的線上平台；GitHub Pages 則是把網頁發布成網址。

先記住：

Git 管理版本；GitHub 協作與儲存；Pages 發布網頁。

2. 三個區域

Working Directory
你正在修改的檔案
→
Staging Area
準備提交的修改
→
Repository
已保存的版本歷史

對應指令：git add 把修改放進暫存區；git commit 把暫存內容保存成版本。

3. 第一個完整流程

git init # 建立 repository git status # 查看目前狀態 git add . # 把修改放進 Staging Area git commit -m "Add first version" # 建立第一個版本紀錄 git log # 查看歷史

這就是最基本的 Git 工作流：看狀態 → 暫存 → 提交 → 查看歷史。

4. 重要名詞

Repository

一個專案及其版本歷史。

Commit

一次有意義的版本快照。

Branch

從主線分出去的開發路線。

Remote

線上的遠端 repository。

Merge

把一條分支的修改合回另一條。

Pull Request

請隊友審查並合併修改的提案。

指令任務：從零建立版本

任務 1/6：輸入 git init
提示：先建立 repository。

指令小抄

查看狀態
git status

確認哪些檔案被修改、哪些已暫存。

查看差異
git diff

查看尚未加入暫存區的內容差異。

建立分支
git switch -c feature-login

建立並切換到新功能分支。

復原已分享修改
git revert <commit>

用新的 commit 反向修正舊版本。

Conflict 視覺化

兩個分支改到同一段時，Git 無法自動決定要留哪一邊。你要閱讀 Current Change 和 Incoming Change，手動整理成 Resolved Result，再提交修正。

Reviewer NPC / Fake CI

Reviewer 問題

這個 PR 改了什麼？有測試嗎？會影響主流程嗎？

CI 檢查

先確認檢查綠燈，再決定是否 Merge。紅燈代表需要先修正。

Boss：完成一次安全合併

請依序選擇正確流程：不要直接在 main 上亂改，先建立分支、提交修改、開 PR、通過 CI，最後才合併。

第 1 步：你要先做什麼？

完成後你應該能說出

  • Git 用來記錄版本，GitHub 用來線上協作。
  • git add 是暫存，git commit 是建立版本。
  • branch 讓功能開發不直接影響 main。
  • PR 是審查與合併的協作流程。
  • Conflict 要人工整理，CI 通過後再合併。
